# taryam-cyber

## متغيرات البيئة المطلوبة على Vercel

| المتغير | ملاحظات |
|---|---|
| `AUTH_SECRET` | **إلزامي، 32 حرفًا على الأقل.** بدونه يرفض الخادم الدخول ورسائل الذكاء الاصطناعي (503). يُستخدم أيضًا لتشفير سجلات المستخدمين، فلا تغيّره دون ترحيل السجلات. لتوليد قيمة: `openssl rand -base64 48` |
| `BLOB_READ_WRITE_TOKEN` | إلزامي للحسابات والحصص. |
| `BLOB_STORE_ID` | معرّف مخزن Blob الحالي. |
| مفاتيح المزوّدين | `DEEPSEEK_API_KEY` و`OPENAI_API_KEY` وغيرها، كما كانت. |

## بعد النشر: ترحيل السجلات القديمة

النسخ السابقة حفظت سجلات المستخدمين وسجل بحث DeHashed في مسارات عامة يمكن تخمينها.
الحساب يُرحَّل تلقائيًا عند أول دخول له، ولترحيل الباقي:

```sh
# تجربة بدون كتابة
AUTH_SECRET=... BLOB_READ_WRITE_TOKEN=... BLOB_STORE_ID=... node scripts/migrate-legacy-blobs.js
# التنفيذ الفعلي
AUTH_SECRET=... BLOB_READ_WRITE_TOKEN=... BLOB_STORE_ID=... node scripts/migrate-legacy-blobs.js --apply
```

## أدوات معطّلة مؤقتًا

- **فحص المنافذ** (`api/portscan.js`): يمكن تجاوز حظر العناوين الداخلية، والتحقق من الملكية موجود في المتصفح فقط.
- **البحث المتقدم / DeHashed** (`api/dehashed.js`): يُرجع بيانات أشخاص آخرين دون التحقق من ملكية الإيميل أو النطاق.

## مختبر RTP (`lab/`)

قسم مستقل عن أدوات الأمن، يُفتح من قائمة ⋮ ← «مختبر RTP» أو مباشرة على `lab/index.html`.
كل الحسابات تتم في متصفح المستخدم داخل Web Worker، وسياسة CSP للصفحة (`connect-src 'none'`)
تمنع أي إرسال للبيانات.

| التبويب | ما يحسبه |
|---|---|
| RTP النظري | RTP دقيق (كسر BigInt) من كل توليفات البكرات، نسبة الفوز، الانحراف المعياري، أعلى ربح، مساهمة كل رمز وكل ميزة (wild، scatter، لفات مجانية بمضاعف وإعادة تفعيل). الإدخال: النموذج، أو JSON، أو CSV (`lab/samples/`). |
| RTP الفعلي | من سجل CSV (bet, win): RTP، فاصل ثقة 90–99.9٪، اختبار z مقابل المعلن، وعدد الجولات اللازم. |
| فحص RNG | اختبارات NIST SP 800-22 الخمسة عشر، ومربع كاي، والارتباط التسلسلي. |
| العدالة المثبتة | تحقق جماعي من التزامات SHA-256 ونتائج HMAC-SHA256، أو سلسلة hashes. |
| مونت كارلو | محاكاة ببذرة ثابتة (xoshiro128** من SHA-256 للبذرة): نفس البذرة تعطي نفس الأرقام ونفس البصمة. |
| التقرير | PDF عربي/إنجليزي برقم تقرير وتاريخ وبصمة SHA-256 لكل مدخل، مع إرفاق المدخلات داخل الـPDF. |

بيانات NIST المرجعية (توسعة e وπ الثنائية) تُولّد بـ `node scripts/make-nist-constants.mjs`،
وملف `lab/samples.js` يُولّد من `lab/samples/*.json` بـ `node scripts/make-lab-samples.mjs`.

## كيف يكسب الكازينو (`lab/casino.html`)

صفحة توعية عامة تُفتح من قائمة ⋮ ← «كيف يكسب الكازينو». تعمل بنفس شروط المختبر: كل شيء
في المتصفح، و`connect-src 'none'`.

- **القاعدة:** ميزة الكازينو، ولماذا الربح مؤقت، ولماذا تُحسب الخسارة من مجموع الرهانات.
- **الألعاب:** السلوتس، شراء البونص، الكراش، Mines، بلاك جاك، الروليت، الجاكبوت، والعروض:
  نسبة الكازينو، وفرصة الفوز، وكيف تأخذ كل لعبة من اللاعب.
- **الحاسبة:** تلعب الجلسة نفسها لـ1,000 لاعب (`lab/core/casino.js`، ببذرة ثابتة) وتعرض كم خرج
  رابحًا، وكم خسر كل رصيده، ومتوسط الخسارة، ورسمًا للرصيد مع الوقت. الروليت دقيقة، والسلوت نموذج
  ديزرت جولد (95.5175٪)، والكراش والـMines بعائد 97٪، والبلاك جاك تقريب للعب المثالي (99.5٪).
- **جلستك:** من مجموع الرهانات والأرباح في سجل الكازينو: كم أخذ الكازينو، وكم مرة دار الرصيد.

## فحص الكازينو (`lab/casino-check.html`)

أداة تعمل على **مواقع وجولات حقيقية**، لا على محاكاة. تُفتح من قائمة ⋮ ← «فحص الكازينو».

1. **فحص الموقع** (`api/casino-check.js` + `api/_casino.js`): يزور الخادم الرابط كما يراه أي زائر ويرجع
   نتائج موثقة بدليل من الصفحة: الترخيص (GCGRA الإماراتي، أو رخص خارجية مثل كوراساو/أنجوان/مالطا، أو
   «مرخّص» بلا جهة)، طرق الدفع (عملات رقمية فقط، وكلاء دفع)، الدعم عبر تلغرام/واتساب، الروابط البديلة
   وVPN، شروط البونص، أدوات اللعب المسؤول، مزوّدو الألعاب وهل يحمّل من خوادمهم فعلًا، استهداف الإمارات،
   وعمر النطاق (RDAP)، والشهادة، وموقع الخادم (ipwho.is)، ورؤوس الأمان. درجة خطر من 100 بثلاث مستويات.
   كل مضيف يُتّصل به — بما فيه كل قفزة تحويل — يُحلّ ويُرفض أولًا إن كان عنوانه داخليًا. الحد 20 فحصًا
   يوميًا لكل IP كما يراه Vercel (لا `guestId` من المتصفح)، والعدّاد مشفّر في مسار غير قابل للتخمين
   (`_store.js`)؛ بلا `AUTH_SECRET` أو `BLOB_READ_WRITE_TOKEN` ترفض الأداة العمل.
   كثير من المواقع تحجب الخوادم (Cloudflare 403): عندها يُحكم من اسم النطاق والسجل والخادم، وتفتح خانة
   «الصق مصدر الصفحة من متصفحك» فيُحلَّل المحتوى الحقيقي في المتصفح بالمنطق نفسه (`lab/core/site.js`،
   نسخة مولَّدة من `api/_casino.js` بـ `node scripts/make-site-core.mjs`) ويُدمج مع نتائج الرابط.
2. **إثبات جولة** (`lab/core/stake-fair.js`): من بذرة الخادم المكشوفة وبصمتها وبذرة اللاعب والـnonce
   يعيد حساب Mines وDice وLimbo وPlinko بخوارزمية Stake والمواقع المقلدة لها، ويقارن بما عرضه الموقع.
3. **تحليل سجل الرهانات** (`lab/core/history.js`): يقرأ جدول «رهاناتي» منسوخًا كما هو (تواريخ، معرّفات،
   عملات، مضاعفات، أرقام عربية) ويمرره لتحليل الجلسة القائم (`lab/core/actual.js`): العائد الفعلي
   وفاصل الثقة والفرق عن المعلن.

الجزءان 2 و3 يعملان في المتصفح فقط؛ سياسة الصفحة `connect-src 'self'` تسمح بطلب واحد: واجهتنا.

## Mines من أ إلى ي (`lab/mines.html`)

عرض على لعبة Mines الحقيقية (مزوّد Turbo Games) بأرقامها هي، كلّه في المتصفح (`connect-src 'none'`):

1. **الجولة محسومة قبل النقرة:** البصمة المعروضة قبل الجولة والبذرة المكشوفة بعدها من زرّ «العدالة» في اللعبة؛
   SHA-256(البذرة) يجب أن تساوي البصمة.
2. **كم يأخذ في كل نقرة** (`lab/core/mines-math.js`): احتمال الانفجار والوصول لكل نقرة بالضبط (C(25−M,k)/C(25,k))،
   المضاعِف العادل مقابل ما تعرضه اللعبة — تُكتب مضاعِفات اللعبة من الشاشة فيُستخرج العائد الذي تدل عليه (نسخة مقلّدة
   تدفع أقل تنكشف هنا) — وتجربة نقرة نقرة، وما تعنيه بعد n جولة (الخسارة المتوقعة وفرصة الخروج رابحًا بالضبط).
3. **رهاناتك الحقيقية:** سجل «رهاناتي» ملصوقًا كما هو مقابل 96٪ المعلنة.
4. **الطبقة الثانية:** اللعبة أصلية ومرخّصة؛ النصب في الموقع غير المرخّص — رابط إلى فحص الكازينو.

## الاختبارات

لا تحتاج اختبارات الخادم أي حزمة خارجية (Node 22):

```sh
node --test "test/api/**/*.test.js"
node --test "test/lab/**/*.test.mjs"
```

اختبار المتصفح يحتاج Playwright:

```sh
npm install --no-save --no-package-lock playwright && npx playwright install chromium
node --test "test/ui/**/*.test.js"
```

تعمل الاختبارات نفسها تلقائيًا على GitHub Actions (`.github/workflows/tests.yml`).
